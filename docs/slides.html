The problemCode drifts from intent, silently

  • Code changes every day. Specs, API contracts, READMEs and tests rarely keep up.
  • Linters check syntax. Tests check what someone remembered to test.
  • Nothing checks that a change still matches the intent, until it becomes an incident, a broken onboarding or a wrong decision.
  • With coding agents the code moves even faster, and every new chat starts without the history.

KairosAn intent-drift guardian powered by IBM Bob

git diff→ intent sections
SPEC · OpenAPI · README · tests→ IBM Bob
kairos mode→ Drift Report→ Bob fixes
kairos-fix mode
  • Every finding has evidence on both sides (file:line), a severity and a proposed resolution.
  • Kairos does not assume the code is right: for each finding, which side is the truth?
  • Runs where drift should be caught: kairos check, pre-push hook, GitHub Action with a PR comment.

Living docs: continuity between sessionskairos init · kairos-dev mode · kairos handoff

  • docs/kairos/: SPEC, PLAN, PROGRESS, DECISIONS, one file per task, HANDOFF.
  • Pointers in the Bob mode, CLAUDE.md and AGENTS.md: every agent reads HANDOFF first. A new chat starts with "continue".
  • A post-commit hook logs progress; kairos fix logs decisions; check flags stale docs.
  • Unlike context compaction: explicit, reviewed in git, shared by Bob, Claude Code and Codex.
  • Dogfooded: Kairos was built this way. HANDOFF (3.8k chars) + one task file instead of ~70k chars of docs.

How IBM Bob powers it

  • bob run --mode kairos --format json with --max-cost and --max-turns
  • 4 custom modes: kairos (read-only), kairos-fix (docs/tests via fileRegex), kairos-fix-code, kairos-dev
  • Whole-repo understanding: Bob opens the code it needs (8 tool calls on A/B/C, 1 on the control)
  • Document understanding: Markdown specs, OpenAPI, READMEs, tests
  • Agent mode for fixes; same path in CI via the Action
